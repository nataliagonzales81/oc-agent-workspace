## [0.1.1] - 2026-09-26

### Fixed

**The README's install command did not work.** `go install
github.com/nataliagonzales81/oc-agent-workspace@latest` fails with *does not
contain package* — the module root has no Go package, because the tool lives
under `cmd/`. The install line needs `/cmd/ocaw`, which is now what the README
says, with the reason.

It shipped in `v0.1.0` and was found by running the install rather than reading
it. `TestReadmeExamplesRunAsWritten` executes every `ocaw` line in the README
and could not catch it, because `go install` is not an `ocaw` line — the one line
a first-time user runs first was the one line nothing tested. There is now a test
that resolves the install path against the repository and fails if it names a
directory with no `package main` in it.

## [0.1.0] - 2026-09-26

The first complete build. Fourteen tasks in a dependency order, each leaving
`go test ./...` green and ending in something runnable, then a contract-lock
harness on top.

### Added

**The JSON envelope is the interface.** One line of JSON on any non-TTY stdout,
precedence `--json` > `--quiet` > TTY detection, a closed set of `error.code`
values an agent branches on instead of message text, and nine exit codes
(`0` ok, `1` internal, `2` usage, `3` precondition, `4` validation,
`5` invariant, `6` lock held, `7` not found, `8` needs confirmation).

**Commands.** `init` builds the workspace and detects the project from marker
files; `doctor` runs seven health checks and emits every finding rather than the
first; `status` is a cheap orientation summary with no subprocesses and no lock;
`task` drives the DAG (`add`, `set`, `dep`, `rm`, `show`, `list`, `next`);
`verify` runs a gate as an argv and records every attempt; `workflow` and
`report` manage the authored half of the generated markdown; `schema` emits a
JSON Schema for any command's payload; `version` reports the build.

**The DAG refuses what an agent would get wrong.** Unique ids, resolvable deps,
an acyclic graph, `in_progress` only when every dep is satisfied, a task with a
dependent in flight may not be parked, `done → in_progress` needs `--yes`, and
`cancelled → done` is refused outright.

**Verification that tells you when to stop.** Every attempt is recorded with its
real exit code and a hash of its full output; three consecutive identical
failures set `stuck`, which `task next` and `status` surface. ocaw never retries
a gate on its own.

**Drift is detected, not tolerated.** `WORKFLOW_STATE.md` carries a SHA-256 of
its own generated half. A hand-edit is `render_drift`; `ocaw report --write` is
the repair. The CLI never parses prose.

**A single-writer lock that fails fast.** `O_EXCL`, never blocks, broken after
15 minutes or a dead holder on the same host, with the reason in a warning.

**Stdlib only.** No `require` block, no `net/http`, a ~200-line internal YAML
subset that errors rather than guessing, and a refusal to read `.env`, `.netrc`,
`*.pem`, `id_*`, or anything under `~/.ssh`.

### Contract

Nine JSON Schemas, **generated by reflection from the payload structs** rather
than written beside them, committed and `go:embed`ed with a test that
regenerates and compares. 32 goldens under `testdata/goldens/`, compared byte
for byte with three exact-value substitutions — the workspace path, RFC3339
timestamps, and the Go version — and nothing else. 14 acceptance tests, one per
criterion, with the criterion-to-test map checked against the source.

### Fixed during the build

Six defects the tests caught that reading the code would not have:

- a `CommandContext` deadline killed only the direct child, so a grandchild
  holding the output pipe made a 200 ms timeout take 5 s
- `AddTask` validated only dangling deps and cycles, so `add --status
  in_progress` was caught by the save path as `write_failed` rather than
  `deps_unmet`
- Go's `flag` stops at the first positional, so `task set 1 --status done`
  ignored the flag and reported that nothing changed
- a global flag *after* a subcommand was parsed and then ignored
- `cell()` was escaping pipes in prose bullets, rewriting the author's sentence
- the goldens pinned `runtime.Version()`, so they only passed on one toolchain

### Known limitations

- The binary name `ocaw` may change; the module path and repository do not.
- The goldens are stricter than the schemas on purpose: adding a payload field
  fails the goldens, and regenerating them is how that change gets reviewed.
- `verify_cmd` is a convention recorded once from a marker file, not a
  discovery. `ocaw doctor` reports it as stale rather than re-detecting it.
- `lint_cmd` is recorded only for Go, where `go vet` ships with the toolchain.
